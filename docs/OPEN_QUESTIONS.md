## SyncStateRepository без вызовов из кода счётчика

**Что обнаружено:** после перевода обмена на ulsync маркеры `lastSyncedAt` / `lastExportedAt` приложением не читаются.

**Где:** `lib/src/domain/sync/repositories/sync_state_repository.dart` и impl.

**Почему не исправлено здесь:** промпт шага 15 запрещает удалять класс, если он не нужен «ещё чему-то»; вычистка мёртвого типа — не этот шаг.

## У `UlsyncClient` нет `stopLive()`

**Что обнаружено:** отмена подписки на `SyncEvent` не рвёт HTTP SSE; флаг `_liveStarted` не сбрасывается; повторный `live()` на том же клиенте не открывает новый поток.

**Где:** `ulsync-dart/lib/src/engine/sync_engine.dart` (`_liveStarted`, `_runLive`, `close()`).

**Почему не исправлено здесь:** чужой репозиторий; в приложении обход — `close()` клиента и `invalidate(ulsyncClientProvider)` при уходе в фон.

## Live не открывается, если первый syncOnce при старте не удался

**Что обнаружено:** сервер упал при уже открытой ленте — устройства после подъёма сами онлайн (сценарий J шага 16). Приложения стартовали при выключенном сервере — после подъёма без Stop+Run лента не оживает: иконка офлайн, плюс на А не доезжает.

**Где:** `lib/src/infrastructure/sync/controllers/ulsync_live_controller.dart`, `_syncThenLive`: провал `syncOnce` ставит `disconnected` и **не** вызывает `live()`. Reconnect в `ulsync-dart` (`LiveSession`) стартует только после `live()`.

**Почему не исправлено здесь:** шаг 17 product-код не чинит. Дефект шага 16. Чинить отдельным PR в `spike/ulsync-test`, не в чате проверки круга.

**Resolution (шаг 16b, PR `spike/27-16b-live-startup`):** `_syncThenLive` вызывает `live()` даже после провала открывающего обмена; на `SyncConnectionRestored` повторяется `syncOnce`, если старт был без сервера. Закрыто в #27.

## Локальные журналы счётчика не сходятся без бэкфилла markChanged

**Что обнаружено:** на одном аккаунте Supabase два устройства показывают разное число (ручной прогон 16b: 79 vs 76). Иконка «На связи» и обмен новых плюсов не закрывают исторический разрыв. Число на экране — длина локального op-log, не снимок сервера. В ulsync уходит только то, что приложение вызвало `markChanged` после append.

**Где:** `IncrementCounterUseCase` (`append` + условный `markChanged`); `LocalOpLogRepositoryImpl` (scope `user:<id>` / `anonymous`); `UlsyncClient.syncOnce` / `_pushDirty` в пакете. Наблюдение: TEMP_16b сценарий C, 2026-09-12.

**Почему не исправлено здесь:** шаг 16b чинит только `live()` после провала открывающего `syncOnce`. Сходимость истории — отдельная задача **приложения**: при логине / первом обмене пометить локальные операции, которых нет в метаданных ulsync, затем `syncOnce` до пустой dirty-очереди. Пакет не сканирует чужой журнал; API «список всех сущностей» в адаптере нет. Не пакет, не круг 2.
